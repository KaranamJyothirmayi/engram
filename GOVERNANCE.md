# Governance

## Roles

### Maintainer

Currently: [@KaranamJyothirmayi](https://github.com/KaranamJyothirmayi)

Responsibilities:
- Reviewing and merging pull requests
- Triaging issues and setting priorities
- Publishing releases
- Enforcing the Code of Conduct
- Maintaining CI/CD, security policy, and legal documents (CLA, LICENSE)

Maintainers have write access to the repository and are the final decision-makers on
all technical and governance matters.

### Contributor

Anyone who has had a pull request merged into `main`.

Contributors are listed in the GitHub contributors graph and credited in release notes.
Consistent, high-quality contributions may lead to an invitation to become a maintainer.

### Community Member

Anyone who participates in issues, discussions, or code review — even without merged code.
All community members are expected to follow the [Code of Conduct](CODE_OF_CONDUCT.md).

---

## Decision Making

- **Routine changes** (bug fixes, docs, tests): reviewed and merged by the maintainer.
- **New features**: discussed in the linked issue before implementation begins.
- **Breaking changes**: require maintainer sign-off and a `workflow:breaking-change` label.
- **Governance changes**: discussed publicly in a GitHub issue for at least 7 days before
  taking effect.

---

## Becoming a Maintainer

There is no formal process yet. If you have made multiple quality contributions and are
interested in a larger role, open a GitHub Discussion and we can talk.
